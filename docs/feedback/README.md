# Feedback de uso real

Un archivo por conversación con alguien que usó la app, con el nombre
`AAAA-MM-DD-<persona>-<tema>.md`. Copiar `plantilla.md` y completarla el
mismo día, mientras está fresca.

Por qué: el dato más valioso no es qué features se piden, sino qué se usa,
qué se abandona y dónde se traba la gente. Eso se olvida rápido si no se
escribe.

Cuando un problema reportado se arregla, dejarlo cubierto para que no
vuelva (un test si es lógica, o una regla en `CLAUDE.md` si es un error
fácil de repetir) y anotar en el archivo de feedback qué se hizo.
